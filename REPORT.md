# 📑 Звіт про проєкт «Internship Tracker»

---

## 1. Мета та завдання проєкту

Метою проєкту є створення простої, мінімалістичної та ефективної вебсистеми для студентів, яка дозволяє організувати процес працевлаштування та пошуку IT-стажувань.

### Основні завдання:
1. Зберігання вакансій та стажувань (наприклад: *EPAM — QA Trainee, SoftServe — Python Internship*).
2. Відстеження воронки відбору за 6 статусами:
   $$\text{"Знайдено"} \longrightarrow \text{"Подано заявку"} \longrightarrow \text{"Зацікавило"} \text{ або } \text{"Відмова"}$$
3. Збір базової статистики та розрахунок успішності (**рівень зацікавленості**).
4. Фіксація нагадувань про дату інтерв'ю чи дедлайн.
5. Завантаження стажувань із зовнішнього API в базу даних.
6. **AI-аналіз відповідності**: автоматичне порівняння вимог вакансії (наприклад: *Python, SQL, REST*) зі списком навичок студента.

---

## 2. Технологічний стек

* **Бекенд:** Python 3.13, Django 6.1, MySQL 8.4 LTS.
* **Фронтенд:** Vanilla HTML5, Vanilla CSS3 (мінімалістичний світлий дизайн без зайвих бібліотек), чистий JavaScript.

---

## 3. Архітектура та структура бази даних

Проєкт реалізовано за архітектурою **MVT (Model-View-Template)**.

### 3.1. Моделі даних (`tracker/models.py`)

1. **`StudentProfile` (Профіль студента)**:
   - `full_name` — ім'я кандидата.
   - `skills` — список навичок через кому (наприклад: `Python, SQL, REST`).
   - Метод `get_skills_list()` — повертає нормалізований список навичок.

2. **`Internship` (Вакансія / Стажування)**:
   - `company` — назва компанії (*SoftServe, EPAM, Genesis*).
   - `position` — позиція (*Python Internship, QA Trainee*).
   - `status` — поточний статус (`found`, `applied`, `offer`, `rejected`).
   - `required_skills` — вимоги до вакансії (*Python, SQL, REST*).
   - `reminder_date`, `reminder_text` — дата і нотатка нагадування.
   - `url` — посилання на вакансію.
   - Метод `ai_match(profile)` — алгоритм зіставлення вимог із профілем.

---

## 4. Алгоритм AI-порівняння навичок

Алгоритм виконує порівняння множини вимог вакансії $R$ із навичками студента $U$:

$$S = \frac{|R \cap U|}{|R|} \times 100\%$$

* **Matched Skills:** навички, що є і у вимогах, і у студента (підсвічуються зеленим `✓`).
* **Missing Skills:** технології, яких бракує студентові для повного закриття вимог (підсвічуються червоним `⚡`).

Наприклад:
* **Вимоги вакансії:** `Python, SQL, REST`
* **Навички студента:** `Python, SQL, REST`
* **Результат:** $100\%$ Match, 0 прогалин.

## 5. Опис інтерфейсу користувача

1. **Головна сторінка (`/`):**
   - Вкладки-фільтри за статусами (Всі, Знайдено, Подано заявку, Зацікавило, Відмова) з лічильниками кількості.
   - Картки вакансій із даними компанії, AI Match бейджем, нагадуванням та швидкою зміною статусу в один клік.
2. **Форма редагування (`/edit/<id>/`):** вакансії додаються автоматично через синхронізацію з Jobicy, ручного додавання немає.
   - Компактна форма для введення даних.
3. **Завантаження вакансій з API в базу даних (автоматично при вході, реєстрації та вході гостем; сортування списку кнопкою «Сортувати», параметр `?sort=`):**
   - Відправка HTTP-запиту методом `GET` до REST API Jobicy (`https://jobicy.com/api/v2/remote-jobs`) з параметрами в URL (`tag`, `count`) та заголовком `Accept: application/json`.
   - Обробка JSON-відповіді: назва посади, компанія, регіон, посилання, зарплата, опис. З кожного запису створюється вакансія в таблиці `Internship` (статус «Знайдено»); сира JSON-відповідь зберігається в полі `raw_json`. RSS і парсинг HTML-сторінок не використовуються.
   - Захист від дублікатів за унікальним `external_id`; статус відбору при повторному завантаженні не змінюється.
   - AI-розрахунок % відповідності вимог із навичками студента для кожної завантаженої вакансії.
   - Дані надає Jobicy (jobicy.com).
   - **Цикл запит-відповідь:** подання аналізують `request.method` (`GET` — читання, `POST` — дії зі зміною даних, `PUT` — оновлення, `DELETE` — видалення), беруть параметри з `request.GET` / `request.POST` і повертають `HttpResponse` зі `status_code` та заголовком. REST-ресурси: `/api/vacancies/` і `/api/vacancies/<id>/`.
4. **Статистика та діаграми (`/stats/`):**
   - Фільтрація за часовими рамками: *Ввесь час*, *Останні 30 днів* (місяць), або *Вибраний період* (за полями «Від» та «До»).
   - Діаграма розподілу вакансій за статусами, побудована бібліотекою Matplotlib на сервері й віддана як PNG через `HttpResponse` (`/stats/chart.png`), з перемиканням між круговою та стовпчиковою.
   - KPI-картки: всього вакансій за період, кількість «Зацікавило», відмов, рівень зацікавленості (%) та візуальна воронка відбору.
4a. **Режим прогалин (`/?gaps=1`):**
   - Для кожної вакансії виводиться перелік навичок, яких бракує порівняно з профілем; вакансії сортуються від найменшої кількості прогалин; зверху показано найчастіші прогалини серед усіх вакансій.
4b. **Реєстрація та вхід (`/register/`, `/login/`, `/logout/`):**
   - Реєстрація (`GET` — форма, `POST` — створення користувача й автоматичний вхід), вхід (перевірка логіна й пароля, створення сесії), вихід (`POST`). Пароль зберігається у вигляді хешу, правила складності перевіряє Django.
   - Профіль студента: для кожної відміченої технології обирається рівень володіння (Beginner, Junior, Middle, Senior; для English шкала CEFR A1–C2), що зберігається в проміжній моделі `ProfileSkill` (M2M `StudentProfile.known_skills` через `through`).
   - Ролі: незалогінений, гість (група `Guest`: права `view_*` та `sync_vacancies`; починає з порожнього списку, може шукати вакансії, але не змінювати їх) і користувач (група `User`, повний доступ до власних даних). Перевірка прав виконується у представленнях (`permission_required_for`, `has_perm`), а не лише в шаблонах.
   - Усі сторінки захищено `@login_required`; вакансії (`Internship.user`) і навички (`StudentProfile.user`) прив'язано до користувача, тому кожен бачить і змінює лише свої записи.
5. **Профіль студента (`/profile/`):**
   - Чек-лист технологій (з можливістю дописати власні) для AI-матчингу та режиму прогалин.
