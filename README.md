# Internship Tracker

Django-застосунок для обліку IT-стажувань: вакансії автоматично завантажуються з Jobicy API, у кожної є статус відбору, нагадування та AI-збіг навичок студента з вимогами вакансії.

## Можливості

- **Вакансії:** після входу, реєстрації або входу гостем паралельно завантажуються 9 категорій Jobicy (Python, QA, JavaScript / Frontend, Java, DevOps, Data Science, .NET / C#, PHP, C++). Помилка однієї категорії не блокує решту й показується попередженням. Повторне завантаження не створює дублікатів.
- **Список «Вакансії»:** вкладки за статусами (`Знайдено` → `Подано заявку` → `Зацікавило` / `Відмова`), швидка зміна статусу, кнопка «Нецікаво», кнопка «Сортувати» (вибрана категорія йде першою), режим прогалин (`?gaps=1`).
- **Заявки (CRUD):** сторінка заявки з редагуванням, видаленням і нагадуваннями; найближчі нагадування показуються над списком.
- **AI-збіг навичок:** перетин вимог вакансії з навичками профілю, відсоток збігу та прогалини. Якщо вакансія вимагає рівень (Junior, Middle, Senior, береться з Jobicy), якщо рівень навички нижчий за потрібний, у вакансії показується позначка «Необхідний рівень (Python): Middle», а навичка дає половину бала. Рівні володіння задаються лише для мов програмування та English.
- **Валідація:** введені дані перевіряються регулярними виразами (`re`, файл `tracker/validators.py`): імʼя користувача, нотатки, текст нагадування, власні навички; повідомлення про помилки українською.
- **Профіль:** чек-лист технологій і рівні володіння (Beginner–Senior, для English CEFR A1–C2).
- **Статистика:** воронка статусів, діаграма Matplotlib, фільтр за періодом (лише для ролі «Користувач»).
- **Довідкові сторінки:** вакансія, компанії та навички (`/vacancies/<id>/`, `/companies/`, `/skills/`); окремої вкладки каталогу немає.

## Стек

Python 3.12+, Django 6.1.2, MySQL 8.4 LTS (mysqlclient), requests, Matplotlib, Bootstrap 5 (локальна копія) і власний CSS.

## Ролі

| Роль | Як отримується | Що може |
|---|---|---|
| Незалогінений | без входу | головна сторінка, вхід, реєстрація, вхід гостем |
| Гість | кнопка «Увійти як гість» (група `Guest`) | лише перегляд власного автозавантаженого списку вакансій; без зміни статусів, профілю та статистики |
| Користувач | реєстрація (група `User`) | повний доступ до власних заявок, нагадувань, профілю та статистики |

Права перевіряються на сервері (`PermissionRequiredMixin`, `permission_required_for`); приховані кнопки в шаблонах лише спрощують інтерфейс. Групи створюються автоматично після `python manage.py migrate`.

## Запуск

1. Віртуальне середовище та залежності (папка `venv/` у репозиторій не входить):

```bash
python -m venv venv
venv\Scripts\activate
python -m pip install -r requirements.txt
```

Для Linux/macOS: `source venv/bin/activate`.

2. База даних MySQL 8.4 LTS (Django 6.1 не працює з MySQL 8.0):

```sql
CREATE DATABASE internship_tracker CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'tracker'@'localhost' IDENTIFIED BY 'ваш_пароль';
GRANT ALL PRIVILEGES ON internship_tracker.* TO 'tracker'@'localhost';
GRANT ALL PRIVILEGES ON `test\_%`.* TO 'tracker'@'localhost';
```

Останній `GRANT` потрібен, щоб `python manage.py test` міг створити тестову базу.

3. Змінні оточення: скопіюйте `.env.example` у `.env` (файл у `.gitignore`) і заповніть:

```
DJANGO_SECRET_KEY, DJANGO_DEBUG, DJANGO_ALLOWED_HOSTS,
DB_NAME, DB_USER, DB_PASSWORD, DB_HOST, DB_PORT
```

4. Міграції та демо-дані:

```bash
python manage.py migrate
python manage.py seed_data
```

Демо-вхід: `demo` / `demo12345`, або кнопка «Увійти як гість».

5. Запуск: `python manage.py runserver`, далі http://127.0.0.1:8000/

Ручне завантаження вакансій: `python manage.py sync_jobs --username demo --tag Python`.
